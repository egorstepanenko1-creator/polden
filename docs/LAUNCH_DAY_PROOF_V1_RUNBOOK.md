# Launch Day Proof v1 — ручной прогон

Цель: доказать цепочку **контент → ссылка с UTM → заказ с атрибуцией → Content Performance**.

## Предусловия

- Запущен backend CRM (`npm run dev` в `backend`), известны `CRM_INTERNAL_TOKEN` и URL API.
- Для **реальных** ссылок на сайт (не `example.invalid`): в `backend/.env` задан валидный `PUBLIC_SITE_ORIGIN` (https-прод или локальный `http://localhost:…` для dev).
- В CRM открыт фронт с тем же `VITE_CRM_TOKEN`, что и `CRM_INTERNAL_TOKEN`.
- Есть ветка/филиал и позиции меню на дату, чтобы публичный заказ прошёл quote (или используйте уже известный рабочий сценарий заказа).

## Happy path

1. **Материал**  
   В CRM → раздел **Контент** → **Новый материал**.  
   Канал `VK`, укажите **путь лендинга** (например `/menu`) или полный **target URL**.  
   Заполните **utm_campaign** и **utm_content** (для однозначного матча в Performance).  
   Статус при желании **APPROVED** → **Сохранить**.

2. **Проверка ссылки**  
   Убедитесь, что **нет** предупреждения «небезопасный origin» (если есть — исправьте `PUBLIC_SITE_ORIGIN` на бэкенде).  
   Скопируйте **сгенерированную ссылку** (кнопка «Копировать»).

3. **Открытие ссылки**  
   Откройте ссылку в браузере (в dev — на том же origin, что и публичное меню/заказ).  
   Убедитесь, что в адресе есть нужные UTM и при необходимости `landing_path`.

4. **Тестовый заказ**  
   Оформите заказ через **публичный** поток (`POST /api/public/delivery-orders`), передав в теле объект **`attribution`** с теми же полями, что в ссылке, например:  
   `utm_source`, `utm_campaign`, `utm_content`, при наличии в ссылке — `landing_path` (тот же путь, что у материала).  
   Фронт заказа должен собирать attribution из query (если у вас так уже сделано); иначе — один раз руками через API/curl.

5. **Content Performance**  
   Вернитесь в **Контент**, нажмите **Обновить список**.  
   У нужной строки должны вырасти **Заказы** и **Выручка**; при фильтре **Есть заказы** строка остаётся в списке.

## Запись аудита (Launch Drill v1)

Чтобы зафиксировать прогон для стейджинга/прода с доказательствами в БД:

1. CRM → **Launch Drill** → выберите тот же материал → **Старт дрилла** (сохраняются ожидаемый `generatedUrl` и снимок `PUBLIC_SITE_ORIGIN`).
2. Выполните шаги happy path выше (ссылка → заказ → проверка Performance).
3. В карточке дрилла укажите **SUCCESS** / **PARTIAL** / **FAILED**, при необходимости **order id**, **выручку (коп.)**, текст атрибуции и **Примечание** → **Сохранить завершение**.
4. История дриллов и деталь доступны на той же странице; при сбоях см. таблицу в конце runbook.

## Автоматическая смок-проверка

Из каталога `backend`:

```bash
npm run prove:launch-day
```

При пустой таблице контента:

```bash
npm run prove:launch-day -- --ensure-test-item
```

Перед выкладкой с проверкой прод-origin:

```bash
npm run prove:launch-day -- --strict-origin
```

## Если что-то не сходится

| Симптом | Что проверить |
|--------|----------------|
| Ссылка с `example.invalid` | `PUBLIC_SITE_ORIGIN` в `.env` бэкенда, перезапуск сервера |
| Заказ есть, Performance = 0 | Совпадение `utm_source` / `utm_campaign` / `utm_content`; если в заказе есть `landing_path`, он должен совпасть с путём материала |
| 401 на API | Заголовок `X-CRM-Token` / `VITE_CRM_TOKEN` |
| Публичный заказ не создаётся | Ветка, дата доставки, состав `items`, quote |
