# Четверг + рецепты: безопасный слой без склада (v1)

## A. Затронутые сущности (только кухня / меню-редактор)

| Сущность | Роль |
|----------|------|
| `Unit` | `g`, если ещё нет |
| `Ingredient` | одна служебная заглушка для публикации версии без многострочного «взрыва» рецепта |
| `IngredientPrice` | 0 ₽/ед. для заглушки (валидный расчёт food cost = 0) |
| `Dish` | 9 позиций четверга, поле `category` (Суп / Горячее / Салат / Гарнир / Напиток / Выпечка) |
| `DishVersion` | `published` v1, поле `notes` с метками `__truth__:confirmed_from_source` или `__truth__:drafted_gap_fill` |
| `DishIngredient` | **ровно одна** строка на версию (связь с заглушкой, 1 г) — не склад и не списание |

Цепочка **слот меню → рецепт**: оператор в «Меню на день» выбирает опубликованный `DishVersion`; в БД это `MenuDayItem.dishVersionId` (заполняется вручную при сохранении слота). Скрипт **не** создаёт `MenuDayItem`.

## B. Явно не трогаем

- `StockMovement`, `InventoryCount*`, `ProductionWriteoff*`, `PurchaseDraft*`, `Supplier*`, остатки
- `DeliveryOrder`, VK-бот, публичный заказ
- Автоматическое создание строк списания по продажам

## E. Запуск сидирования четверга (обязательна целевая точка)

Скрипт **не пишет** `MenuDayItem` и **не меняет** `Branch`, но **требует** `TARGET_BRANCH_ID` (или `--branch-id=`) — проверка, что точка существует, лог id+имя, предупреждение если в имени «Новосибирск». Так нельзя запустить сид «вслепую» без явного операционного контекста.

Из каталога `backend`, `DATABASE_URL` задан:

```bash
# сухой прогон (только чтение БД + план)
TARGET_BRANCH_ID=<id_точки_Чебаркуль> npm run db:seed:thursday-menu:dry

# запись глобальных Dish/Version (как раньше), после проверки ветки
TARGET_BRANCH_ID=<id_точки_Чебаркуль> npm run db:seed:thursday-menu
```

Альтернатива CLI: `node scripts/seed-thursday-menu-safe.mjs --branch-id=<id> [--dry-run]`

Идемпотентно: если у блюда уже есть **published** версия, строка пропускается.

### Совместимость с «только Новосибирск в API»

Если в БД по-прежнему одна точка с названием вроде «Новосибирск · Центр», скрипт **выполнится** (ветка найдена), но выведет **предупреждение**. Вывод четверга в **продажи/VK по рынку Чебаркуль** безопасен только после **исправления данных точки** (rename) и/или env `POLDEN_VK_DEFAULT_BRANCH_ID` / `POLDEN_VK_ORDER_PROBE_BRANCH_ID` на id нужной `Branch`. Сид **не переименовывает** точку.

## E2. Минимальный runbook: четверг в CRM

1. Убедиться в правильном `Branch.id` (Чебаркуль) — при необходимости переименовать точку в данных или зафиксировать id после `db:rename-chebarkul` / ручного правления.
2. `TARGET_BRANCH_ID=<этот_id> npm run db:seed:thursday-menu` (или dry-run сначала).
3. CRM → **Меню на день** → выбрать **ту же** точку → дата **четверга**.
4. Слоты **1–9**: название/цена витрины + привязка **опубликованной** версии рецепта; в селекте группы «Супы», «Горячие», … и метки `[ТТК из файла]` / `[черновик ТТК]`.
5. Сохранить слоты. VK/заказы не трогать в этом шаге — они читают уже заполненные `MenuDayItem` на выбранную точку и дату.
