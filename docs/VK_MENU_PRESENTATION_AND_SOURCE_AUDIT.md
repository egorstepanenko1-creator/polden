# VK: меню в чате и источники правды в CRM

## 1. Где строится ответ на «Меню»

| Шаг | Файл / функция |
|-----|----------------|
| Вход | `POST /api/vk/webhook` → `handleVkIncomingMessage` (`vkBotHandler.js`) |
| Условие | `wantMenu` (текст «Меню» / menu) в состоянии IDLE или в блоке с кнопками |
| Данные | `getCurrentVkMenuDailyItem(prisma)` → `vkMenuContent.js` |
| Текст | `formatVkMenuMessage(item)` → к сообщению добавляется `MSG_MENU_FOOTER` (`vkBotRu.js`) |

Тот же `formatVkMenuMessage` вызывается из `vkOrderHandler.js` при «Меню» внутри структурированного заказа (сброс в IDLE и тот же текст).

## 2. Источник текста «Меню» (презентация)

- **Модель:** `ContentItem`  
- **Фильтр:** `channel = VK`, `contentType = MENU_DAILY`, `status ∈ { APPROVED, PUBLISHED }`  
- **Выбор:** сортировка `publishDate desc`, `updatedAt desc`, одна запись  
- **Поля в сообщении:** `title`, `captionDraft` (сжимаются по длине/числу строк в `formatVkMenuMessage`), опционально ссылка через `buildContentGeneratedUrl` (`contentGeneratedUrl.js`)

Это **анонс/маркетинговый блок из контент-пайплайна**, не автоматический список блюд на доставку.

## 3. Источник заказа «Оформить заказ» (продаваемое меню)

- **Модель:** `MenuDayItem` на дату **«завтра»** (`serverLocalTomorrowISO`) для выбранной `Branch`  
- **Код:** `loadOrderableMenuRows` (`vkOrderMenu.js`) → `vkOrderHandler.startVkStructuredOrder` / шаги корзины  
- **Правда для продажи:** только позиции с **непустым `name`**, как в CRM «Меню на день»

## 4. Где расходятся

| Аспект | MENU_DAILY (VK текст) | MenuDayItem (заказ) |
|--------|------------------------|---------------------|
| Назначение | Показ дня в чате, ссылка на сайт | Расчёт корзины, цены, создание `DeliveryOrder` |
| Синхронизация | Редактор контента | Операционное меню на дату |
| Совпадение состава | Не гарантируется | Единственный источник для бота |

В тексте меню явно сказано: на завтра список и цены — в шаге «Оформить заказ».

## 5. Что изменено в презентации (кратко)

- Первая строка — контекст «анонс CRM» vs «заказ на завтра».  
- Обрезка длинного `captionDraft` (строки и символы), подсказка про сайт/оператора.  
- Короче футер и idle-подсказка; префикс ссылки `Сайт:` вместо путаницы с кнопкой заказа.

## 6. Дублирование сообщений меню

**Причина:** повторная доставка одного и того же события `message_new` от VK (тот же `conversation_message_id` / `id`) приводила к повторному вызову хендлера и второму `messages.send`.

**Исправление:** в `vkBotHandler.js` — кратковременный дедуп по ключу `peerId + id` в памяти процесса (ограничение: один инстанс Node; при нескольких воркерах нужен общий store).

## 7. Ограничения

- Дедуп только при наличии `id` / `conversation_message_id` в объекте сообщения.  
- Сжатие текста может обрезать длинные подписи; полный вариант — по ссылке или у оператора.  
- Readiness `/api/vk-bot/readiness` по-прежнему отдельно проверяет `menuDaily` (ContentItem) и `vkOrderableMenu` (MenuDayItem) — там видно расхождение данных.
