# VK: структурированный заказ v1 (прямой DeliveryOrder)

## До этой задачи

- Бот показывал **контент** MENU_DAILY (текст/ссылка) и собирал **VkLead** (имя, телефон, адрес, дата текстом, комментарий).
- Реальный **DeliveryOrder** создавался только с сайта или из CRM (ручная форма).

## После изменений

- Добавлен поток **«Оформить заказ»**: меню берётся из **MenuDayItem** (та же правда цен, что `computeQuoteKopeks` / сайт).
- При успешном прохождении шагов создаётся **DeliveryOrder** через **`createDeliveryOrderFromInput`** (`sourceChannel: VK`, `status: NEW`).
- В **attributionJson** пишутся `vk_peer_id`, `vk_user_id`, `order_capture: vk_direct_v1`, `utm_source: vk`, `utm_medium: bot` (см. `sanitizeAttribution` в `attribution.js`).
- Поток **лида** и кнопки **Меню** / **Оператор** сохранены; из потока заказа можно переключиться на заявку или меню.

## Пошаговый сценарий (структурированный заказ)

1. Пользователь: **«Оформить заказ»** (кнопка или фраза «оформить заказ» / «сделать заказ»).
2. **Одна точка:** дата доставки = **завтра** по локальному календарю процесса Node (`serverLocalTomorrowISO` — тот же сдиг +1 день, что `dates.js` на фронте; TZ сервера должен совпадать с бизнес-ожиданием).
3. **Несколько точек:** бот просит номер строки из списка (ветки по имени A→Я).
4. Показывается меню с **реальными** позициями и ценами из CRM на выбранную дату.
5. Пользователь вводит корзину **только в поддерживаемом формате** (см. ниже). Иначе — подсказка, без угадывания из свободного текста.
6. Показывается **итог** (quote через `computeQuoteKopeks`). Подтверждение: «да» / «ок» / «подтвердить» / «+»; «назад» — снова ввод позиций; новая строка позиций — замена корзины и пересчёт.
7. Имя → телефон → адрес → комментарий («-» пропуск).
8. Создание заказа; пользователю — **id** и сумма.

## Fallback (только лид)

- Нет **Branch** в БД.
- На «завтра» нет **MenuDayItem** с непустым **name** для выбранной точки.
- Ошибка quote / создания — текст ошибки + предложение **«Оставить заявку»**.
- Пользователь в любой момент может нажать **«Оставить заявку»** — черновик заказа сбрасывается, начинается классический сбор лида.

## Источник меню

- `loadOrderableMenuRows` → `prisma.menuDayItem` по `branchId` + `deliveryDate` (строка `YYYY-MM-DD`).
- Не используется текст поста VK как источник цен; контент MENU_DAILY по-прежнему для кнопки «Меню».

## Создание DeliveryOrder

- `backend/src/vkOrderHandler.js` → `createDeliveryOrderFromInput` без `linkVkLeadId`.
- Прайс и валидация позиций — только **`computeQuoteKopeks`**.

## Состояния FSM (строка `currentState`)

| Значение | Назначение |
|----------|------------|
| `ORDER_PICK_BRANCH` | Выбор точки номером |
| `ORDER_AWAIT_ITEMS` | Ввод корзины |
| `ORDER_REVIEW` | Подтверждение / правка состава |
| `ORDER_C_NAME` … `ORDER_C_COMMENT` | Контакты и комментарий перед созданием |

Поля черновика в **VkConversationState**: `draftBranchId`, `draftDeliveryDate`, `draftCartJson` (JSON массива `{ position, qty }`).

## Формат ввода позиций

Поддерживается **только** явный синтаксис:

- `1x2` или `3х1` / `3×1` (лат. x, кирил. х, ×) — позиция × количество.
- `1 2` — позиция и количество через **пробел** (одна пара в сегменте).
- Несколько пар: разделители **запятая, точка с запятой или перенос строки**, например: `1x2, 3 1`.

Позиции **1–10**, количество **1–99**. Одинаковые позиции в строке **суммируются**.

## Ограничения

- Дата доставки в v1 **фиксирована** как «завтра» (календарь сервера); смена даты в боте не реализована.
- Readiness **vkOrderableMenu** проверяет **первую** точку по имени (A→Я); при нескольких филиалах у другой точки меню может отличаться.
- Лимит длины сообщения VK (4096) — очень длинное меню может обрезаться при отправке.
