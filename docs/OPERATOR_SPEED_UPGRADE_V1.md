# Operator Speed Upgrade v1 (CRM)

Практичное ускорение ежедневной работы оператора доставки обедов с телефона. Без смены доменной модели и без затрагивания публичного API заказа / VK capture.

## Боли, на которые ответ

- Долгий путь к смене статуса (выбор в боковой панели + «Применить»).
- Нет поиска заказа по телефону/имени/адресу/id.
- Мелкие контролы быстрого создания и десять полей количества всегда на экране.
- KPI занимал верх страницы — оператору важнее список заказов на дату.

## Маршруты API

| Метод | Путь | Изменение |
|--------|------|-----------|
| GET | `/api/delivery-orders` | без изменений (`branchId`, `date`) |
| GET | `/api/delivery-orders/search` | **новый**, защищён `X-CRM-Token` |
| PATCH | `/api/delivery-orders/:id/status` | без изменений |

### GET `/api/delivery-orders/search`

Параметры:

- `branchId` (обязательно)
- `q` — при длине **&lt; 2** символов сервер возвращает **пустой массив** (HTTP 200).
- `date` (опционально) — фильтр по `deliveryDate`; если не передан, поиск по всем датам доставки в точке.
- `limit` (опционально) — по умолчанию 40, максимум 80.

Поиск: `LIKE` / `contains` по полям `customerName`, `address`, `id`, `customerPhone` (для телефона дополнительно нормализуется запрос до цифр при длине ≥ 2).

## Мобильный поток (кратко)

1. Вкладка «Заказы и KPI»: сверху блок **Оператор · заказы** — сегодня/завтра, точка, дата, поиск, «+ Заказ», обновить.
2. Список — **карточки заказа** с крупными кнопками: звонок, копия телефона/адреса, «вперёд» по цепочке статусов, отмена.
3. KPI и сводки — в **`<details>`**, по умолчанию свёрнуто.

## Поиск в UI

- Поле «Поиск: телефон, имя, адрес, ID…», debounce ~320 ms.
- Чекбокс **«Искать только в выбранной дате доставки»** (по умолчанию включён): передаётся `date` в API; снят — поиск по всем датам в точке.
- Кнопка «Сбросить поиск».

## Быстрое создание заказа

- Заголовок «Быстрый заказ», крупная зелёная кнопка отправки.
- Канал: **три кнопки** (Вручную / Телефон / VK) + выпадающий список «другой канал» (без «Сайт» для ручного сценария).
- Позиции: **быстрый ввод** строкой + «Применить»; поля 1–10 скрыты под раскрывающимся блоком.
- После успеха список обновляется (`loadOrders`), поиск сбрасывается на стороне родителя.

## Компактный синтаксис позиций

Файл: `frontend/src/operatorCompactItems.js`.

- Форматы: `1x2`, `1×2`, `1*2`, `1:2`, `1/2` (позиция и количество).
- Несколько пар через пробел, запятую или `;`: `1x1 3x1 5x2`.
- Позиции **1–10**, количество **1–99**; повтор той же позиции **суммируется** (потолок 99).
- «Применить» **заменяет** все количества по результату разбора (остальные позиции → 0).

## Статусы

- Основная кнопка **→** переводит на следующий шаг линейной цепочки: NEW → CONFIRMED → KITCHEN → DELIVERING → DONE (если переход разрешён бэкендом).
- Отдельная кнопка **«Отменён»** (CANCELED), когда разрешено правилами.
- Обновление списка **без полной перезагрузки страницы** — локальный merge ответа PATCH.

## VK

- На карточке заказа канал **VK** выделен сильнее; показывается **vkLeadId**, если есть.
- Модалка с префиллом из лида без изменения события `polden-open-order-form`.

## Ограничения

- Поиск на SQLite **без полнотекстового индекса** — при очень больших таблицах возможны задержки; лимит выдачи ограничен.
- Регистр при `contains` зависит от БД/Collation.
- Нет офлайн-режима и push.
