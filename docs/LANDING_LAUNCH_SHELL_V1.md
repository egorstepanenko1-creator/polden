# Landing launch shell v1

Документ описывает обновление **авторитетного** публичного лендинга `project/landing-order/index.html` (без дубликатов в `CRM/crm-mvp/landing-order` и без `new/**`).

## Цели

- Первый контакт: понятно **что за сервис**, **на какой день заказ**, **почему можно доверять** (без отзывов и без выдуманных обещаний).
- Конверсия: CTA рано, форма не «внизу тоннеля», статусы меню и заказа читаемы.
- Сохранение: тот же `API_BASE`, те же `POST /api/public/delivery-orders` / quote / menu-day, поле **`polden_hp`**, атрибуция.

## Бизнес-допущения (как в коде)

- **Дата доставки** в форме — **завтра** относительно локального календаря пользователя (`getTomorrowISO()`), согласовано с прежней логикой.
- Онлайн-заказ **только** при `menuLoadStatus === 'live'` (подтверждённые позиции из API).

## Live vs degraded

- **live** — имена позиций из `menu-day`; заказ разрешён.
- **degraded** — ответ API без пригодных имён; ориентир из fallback, заказ закрыт.
- **illustrative** — сеть/ошибка; fallback, заказ закрыт.

## Поддержка и VK

В начале скрипта:

```js
const POLDEN_LAUNCH_BRIDGE = {
  vkGroupUrl: '',       // например 'https://vk.com/...'
  supportLineHtml: ''    // только согласованная разметка (innerHTML)
};
```

- При непустом `vkGroupUrl` показывается ссылка «Открыть сообщество VK».
- `supportLineHtml` выводится в `#bridge-support-extra` (доверенный контент).

## Ограничения

- Нет отдельной сборки; один HTML + встроенные стили/скрипт.
- `supportLineHtml` — XSS-риск при вставке недоверенного HTML; заполнять только проверенной вёрсткой.
- Юридические реквизиты в подвале — **плейсхолдер** до заполнения человеком.
